# Milestone 4: Network Password Implementation Plan

> **For agentic workers:** Implement task by task (superpowers:executing-plans). Steps use checkbox (`- [ ]`) syntax.

**Goal:** One code on the Core protects the whole network: terminals, bays, and the drives themselves.

**Architecture:** The **Core** becomes a composite block with vanilla `TEFeatureLockable` (lock/unlock/enter code/set code, owner, allowed list — all vanilla) plus `TEFeaturePickup`. Bays and terminals have **no lock of their own**; they ask the Core's lock (single source of truth, no syncing). Drives get a **stamp** in their metadata (`StashNetLock` = `x,y,z|passwordHash` of the Core that locked them) so a drive taken to another network is unreadable unless that network has the same code or is its home Core.

**Tech Stack:** C# (now compiled against the game's own mscorlib — needed for `ReadOnlySpan` in feature overrides), xUnit, vanilla `TEFeatureLockable`, `XUiC_KeypadWindow`.

**Spec:** `docs/PLAN.md` §2.6, roadmap row 4.

## Global Constraints
- Vanilla lock semantics are kept as-is: setting/changing the code clears the allowed list (kicks everyone), owner always allowed, allies may lock/unlock.
- Network access = Core not locked, **or** player is on the Core's allowed list / is owner. No Core TE (old pre-M4 Core) ⇒ treated as unlocked.
- **Server enforces** access on every terminal request (player's PrimaryId via `persistentPlayers`). Bay opening is gated client-side (vanilla storage opening is client-driven; consistent with client-authoritative inventory).
- Drive stamp rules (pure, tested):
  - no stamp → readable; stamp it if the network has a password.
  - stamp from **this Core position** or with the **same password hash** → readable; restamp to the current Core/hash (or clear if the network has no password).
  - unparseable stamp, or other Core + different hash → **unreadable, left untouched** (unlocking a foreign drive = M5 Drive Port).
- Stamps are only written server-side (in `SaveDirty`).
- Bays: retire their own lock's "lock"/"keypad" commands (keep "unlock" so earlier test locks can be removed). Add a "Network code" command that opens the Core's keypad.

## Review Focus
1. **Old Cores placed before M4** have no lock data → treated as unlocked, no errors; checklist tells the owner to re-place them to get the lock.
2. **Owner changes the code** → everyone else loses access immediately; their own drives restamp (same Core position), nothing becomes unreadable for the owner.
3. **Drive moved between two of the owner's networks with the same code** → readable (hash match).
4. **Stolen drive in a thief's network** → listed as "locked to another network", items not shown, data untouched.
5. **Looking at a bay must stay cheap** (activation checks run every frame) → cache the Core lookup per bay for ~1 s.
