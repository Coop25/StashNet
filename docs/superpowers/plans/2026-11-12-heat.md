# Milestone 7 Heat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Scrap Core gives off vanilla heat that scales with its network's drive count (capped), and Storage Terminal use adds a small bump.

**Architecture:** The game-free math (heat formula, emit throttle) lives in `StashNet.Core` with xUnit tests. A new composite tile-entity feature `TEFeatureStashNetHeat` on the Core is ticked by the game (`Chunk.UpdateTick` → `TileEntityComposite.UpdateTick` → features). On the server only, it reports heat via `world.aiDirector.NotifyActivity` on the vanilla workstation rhythm (`AIDirector.GetActivityWorldTimeDelay()`, about 167 real s). `TerminalServer.Handle` adds the terminal bump.

**Tech Stack:** C# (netstandard2.0 Core lib + game-framework mod DLL), Harmony not needed, xUnit, 7DTD XML config.

**Spec:** `docs/superpowers/specs/2026-11-12-heat-design.md`

## Global Constraints
- Game V3.4 b10. The mod compiles against the game's own framework libs (see CLAUDE.md "Build note").
- All balance numbers in `Mod/Config/blocks.xml` as block properties: Core `StashNetHeatPerDrive=0.25`, `StashNetHeatCap=6.5`; Storage Terminal `StashNetHeatOnUse=0.5`.
- Event type `EnumAIDirectorChunkEvent.Campfire`, duration = the vanilla default (720). Never bypass `NotifyActivity` (it handles blood moon, heat setting off, sensitivity).
- Server-side code must never touch XUi/EntityPlayerLocal.
- Build to `dist/` only. Deploy only after the owner says yes and the game is closed.
- Version bump to **0.8.0** (`Mod/ModInfo.xml`, `StashNetMod.Version`).
- Never commit game DLLs or decompiled game code.

## Review Focus
1. **Remote client / dedicated server:** the heat feature must emit only where `ConnectionManager.IsServer`, so heat isn't reported twice on a host with clients. Task 2 guards it. Checked in-game in M9.
2. **World time going backwards** (admin `settime`, or loading a save): the throttle must not stall for days. Covered by the `HeatThrottle` test `TimeWentBackwards_EmitsNow`.
3. **Unreadable drives and open bays:** an unreadable drive still counts as a drive for heat (`Storage.Drives.Count + SkippedDrives`). Drives in a bay someone has open aren't counted for that one report. That's acceptable and noted in the code comment.
4. **Missing/invalid XML values** (a Core block without the heat props, a negative cap): the formula clamps to ≥ 0. A block without props uses 0, so there's no heat and no crash. Covered by `NetworkHeat` tests.
5. **Crafting Terminal requests** (List every 2 s while open) must NOT add the terminal bump. It already has workbench heat. Task 3 checks that the block is `BlockStashNetTerminal` and reads the prop from the block (only the Storage Terminal has it).

- [ ] **Step 1: Write the failing tests** in `HeatTests.cs`:
  - `PerReport_ScalesWithDrives`: `PerReport(12, 0.25f, 6.5f) == 3f`

  - `PerReport_NoDrives_Zero`: `PerReport(0, 0.25f, 6.5f) == 0f`

  - `Throttle_TimeWentBackwards_EmitsNow`: `next = 50_000`, `ShouldEmit(1000, ref next, 1111)` is true and `next == 2111`. Rule: if `nextTime - delay > now` (the last emit is "in the future"), treat it as due.
